# OPS DECK — Update 0009: трајно управување со тимски акаунти

Овој update го поправа backend-от зад страницата **Тим**.

## Што е поправено

- Креирање на нов Supabase Auth акаунт директно од OPS DECK.
- Автоматско креирање/поправка на profile запис.
- Автоматско доделување улога: Администратор / Менаџер / Член.
- Зачувување на пристап до секоја избрана страница.
- Менување на улога и пристап кај постоечки корисници.
- Опционално поставување нова лозинка од Team drawer.
- Бришење корисник директно од OPS DECK.
- Постоечките корисници што се креирани рачно во Supabase се backfill-ираат и можат да се управуваат од OPS DECK.
- Промените во улога/страници се применуваат realtime кај најавениот корисник.
- Backend функцијата враќа точна грешка и request ID наместо општо „Операцијата не успеа“.
- Team страницата прво проверува дали backend функцијата е исправно конфигурирана.
- Netlify Node runtime е сменет од 20 на 22.

## Инсталација

1. Качи ги сите фајлови од update ZIP-от во истиот GitHub repository и Commit changes.
2. Во Supabase → SQL Editor → New query пушти само:
   `supabase/migrations/0009_team_accounts_backend.sql`
3. Не пуштај повторно 0001–0008.
4. Почекај Netlify да заврши нов Production deploy.
5. Не треба нов environment variable ако веќе ги имаш:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` со `sb_secret_...` вредност
6. Во Netlify environment variables, `SUPABASE_SERVICE_ROLE_KEY` мора да биде достапен за Functions / All scopes.

## Проверка

Во OPS DECK → Тим:

1. Додај тест акаунт со нова е-пошта.
2. Избери улога Член.
3. Остави само Почетна, Мој ден и Задачи.
4. Креирај акаунт.
5. Најави се со новиот акаунт во incognito прозорец.
6. Треба да ги гледа само избраните страници.
7. Од owner акаунтот промени му пристап и улога — промената треба да се примени без повторно креирање на акаунтот.

Owner улогата намерно не може да се креира/брише од Team формата.
